# Devices and Revoke Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** List signed-in devices, rename them, and revoke one or all others; a revoked device loses API access within seconds and wipes itself on next contact.

**Architecture:** Server (`/run/media/nahidujjaman-hridoy/5ECC6955CC69288B/terra/server`, branch `feat/devices`): a `devices` table upserted where refresh tokens are issued, a revoked-device check in `JWTMiddleware`, `/me/devices*` endpoints, and `device_revoked` on `account-status`. Client (this repo, branch `feat/devices`): a devices API, a Rust `device_info` command, a wipe-on-revoke step on the existing revoked-session path and before sign-in, and a Devices section in Settings → Security. Two PRs: server first.

**Tech Stack:** Go (gin, GORM AutoMigrate, sqlite tests), Rust (`gethostname` 1.1, already in Cargo.lock), React 19, zustand, vitest.

**Spec:** `docs/superpowers/specs/2026-11-17-devices-design.md`

## Global Constraints

- A device is recorded only for a UUID `device_id`; empty, `"default"` or non-UUID → nothing recorded, no checks.
- Fresh sign-ins (register, login, recovery, OAuth callback/exchange/setup) clear `RevokedAt`; refresh never does.
- Revoke = set `RevokedAt` + revoke that device's live refresh tokens, in one transaction. The current device can't be revoked from the list (`400`).
- Revoked device's requests → `401` with code `DEVICE_REVOKED`; its refresh → the existing plain `401`.
- Names trimmed, 1–100 chars for rename; metadata fields trimmed and capped at 100.
- Wipe only when the server says `device_revoked: true` for this user + device; never on doubt.
- Notice copy: "This device was signed out from another device. Its Shetu data was erased."
- Revoke confirm copy: "Sign out <name>? It loses access now and erases its Shetu data the next time it's online. If it was lost or stolen, also change your password."
- No AI attribution in commits. Server tests: `go test ./...`. Client: `npx vitest run`, `npx tsc --noEmit`, `cargo test --lib`.

## Review Focus

- A fresh sign-in on a device that is still revoked and still holds local data → the client wipes before signing in (Task 4 test `login_on_revoked_device_wipes_first`).
- Revoke of a device that belongs to another user (guessing a `device_id`) → `404`, nothing changes (Task 2 test `revoke_other_users_device_not_found`).
- An access token minted before the revoke, used after it → `401 DEVICE_REVOKED` immediately, not after 15 min (Task 2 test `middleware_rejects_revoked_device`).
- `account-status` with someone else's device id → no `device_revoked` (Task 1 test `account_status_device_revoked_only_for_own_device`).
- The devices list loading fails or is slow → the Security tab still renders with an error/empty state, no crash (Task 5 test).
