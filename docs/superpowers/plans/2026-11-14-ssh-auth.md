# SSH Auth (Agent, Keyboard-Interactive, PuTTY Keys) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Log in with SSH-agent keys automatically, answer server keyboard-interactive prompts (auto from a saved password or via a dialog), forward the agent per host, and import PuTTY `.ppk` keys.

**Architecture:**
- The login sequence moves from `ssh::authenticate_over_stream` into a new `ssh_auth.rs`. It is generic over the russh handler and takes an injected agent and prompter, so it is tested against an in-process russh server.
- Agent discovery lives in `ssh_agent.rs`. The prompt plumbing mirrors the host-key prompt pattern: an event, a pending map, a command, and an app-wide dialog.
- `.ppk` keys are converted to OpenSSH at import by a new Rust command.

**Tech Stack:** Rust (Tauri v2, russh 0.62.6, ssh-key rc.11 with the `ppk`/`encryption` features enabled through russh), React 19 + TS, zustand, vitest + happy-dom.

**Spec:** `docs/superpowers/specs/2026-11-14-ssh-auth-agent-kbdint-ppk-design.md`

## Global Constraints

- **Login order:** `none` probe only when the host has neither a key nor a password (unchanged), then:
  1. the host key;
  2. the agent keys;
  3. the password;
  4. keyboard-interactive.

  Each step runs only if the previous one failed and, once a failure has listed `remaining_methods`, only if that method is listed.
- **Agent key cap:** when the host has a saved password, at most **3** agent keys are tried; otherwise every agent key is tried.
- **Agent location:** the Settings override path (non-empty) wins. Otherwise use `SSH_AUTH_SOCK` on Unix/macOS. On Windows try `\\.\pipe\openssh-ssh-agent`, then Pageant. Agent unreachable or erroring → skip the step silently.
- **Background checks never touch the agent:** a handler with `auto_accept = true` (ping, OS probe) skips the agent step.
- **Interactive** = `!auto_accept && !require_known_host` (the existing host-key rule). Only interactive handlers show the prompt dialog.
- **Keyboard-interactive auto-answer:** saved password present + a round with exactly one prompt whose `echo` is false → answer with the saved password, at most once per connection, and **never** if the password step already ran and was rejected.
- **Non-interactive keyboard-interactive failure text (exact):** "This server needs an interactive login (2FA). Connect in a terminal instead."
- **Prompt event** `ssh-auth-prompt`, payload `{ id, host, port, username, name, instructions, prompts: [{ text, echo }] }`. The command is `answer_auth_prompt(id: String, responses: Option<Vec<String>>)`. `null` means cancel.
- **Prompt timeout** is **5 minutes**. Cancel or timeout → error text "Login cancelled". The connect timeout pauses while a prompt is pending.
- **Saved-key failure falls through.** If everything fails, the error is `"<key error>; then: <last error>"`.
- **Agent forwarding:** host payload `forwardAgent: boolean`, missing means false. It applies to the target's interactive terminal session only. Agent channels are accepted only when the handler's `forward_agent` flag is set; otherwise they are rejected.
  - Toggle label (exact): "Forward SSH agent".
  - Help (exact): "Lets this server use your local SSH keys while you're connected. Anyone with root on the server can use them too. Only enable for servers you trust."
  - No-agent notice (exact): `\r\n[Agent forwarding unavailable: no SSH agent found]\r\n`.
- **Settings:** `sshAgentPath: string`, default `""`, labelled "SSH agent socket", with help "Leave empty to use the system agent (SSH_AUTH_SOCK, Windows OpenSSH agent or Pageant)." It is pushed with the existing `set_ssh_defaults`, which gains `agent_path: String`.
- **`.ppk`:** `convert_ppk(text: String, passphrase: Option<String>) -> Result<String, String>`. Errors are exactly `"PPK_ENCRYPTED"` (encrypted, no passphrase) or `"PPK_BAD_PASSPHRASE"`. Modal copy: "This PuTTY key is encrypted — enter its passphrase" / "Wrong passphrase". The output is OpenSSH text, re-encrypted with the same passphrase when one is given.
- **Never log** prompt answers, agent key material, decrypted `.ppk` text or passwords.
- **No AI attribution** anywhere. Never run `biome check --write` on folders; pass only the changed files.
- **Checks:** `mkdir -p dist && cd src-tauri && cargo test`; `bunx vitest run` (there is no package.json test script); `bunx tsc --noEmit`; `bunx biome check <changed files>`.

## Review Focus

1. **Today's key-only and password-only hosts log in exactly as before:** same order, no new round trips, no agent touched when the host key succeeds. Pinned by Task 1 tests `key_host_skips_agent_on_success` and `password_host_unchanged_without_agent`.
2. **A server listing only `publickey,keyboard-interactive` (no `password`)** with a saved password logs in via auto-answer and never sends a password request. Pinned by Task 1 test `kbdint_auto_answers_when_password_method_absent`.
3. **A broken agent** (socket path exists but isn't an agent, or the agent errors mid-sign) never fails a login that a password would pass. Pinned by Task 2 test `unreachable_agent_path_is_skipped`; the mid-sign error is covered by the Task 1 agent-step error handling and the final review.
4. **The dialog for a connection that was already cancelled or timed out:** a late answer is ignored, there's no panic, and the next prompt still works. Pinned by Task 3 test `late_answer_after_timeout_is_ignored`.
5. **A server opening an agent channel on a host without forwarding** is rejected, and nothing reaches the local agent. Pinned by Task 4 test `agent_channel_rejected_without_flag`.
