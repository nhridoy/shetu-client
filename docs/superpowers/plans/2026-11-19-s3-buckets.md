# S3 Buckets Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an S3 bucket as a third kind of file pane. You can browse it, transfer to and from it through the existing queue, and compare it with another pane. The accounts are saved encrypted in a new synced `storage_accounts` table.

**Architecture:**
- **Accounts:** they live in a new synced table that mirrors `identities` (server and client). The encrypted blob is decrypted only in Rust.
- **Rust side:** a `storage` module builds an OpenDAL S3 `Operator` per pane session and per transfer.
- **Transfer engine:** `io::Side` gains `Remote(Operator)`. A bucket destination writes straight to the final key, which is picked before the copy, so there is no `.part`.
- **Web side:** a bucket pane reuses `FileBrowser` with `hostId = "storage:<accountId>:<bucket>"`. It registers a `StorageFileProvider` whose `type` is `"remote"` and whose `getSessionId()` is the pane id. Transfers and compare then work unchanged once Rust resolves that session id.

**Tech Stack:**
- Rust: Tauri v2, tokio, `opendal` 0.59 (`services-s3`; `services-memory` for tests), rusqlite.
- Web: React 19, zustand, vitest (happy-dom), biome.
- Server: Go + GORM.

**Spec:** `docs/superpowers/specs/2026-11-19-s3-buckets-design.md`

## Global Constraints

- Never add Claude/AI attribution to commits, PRs or replies.
- Formatting:
  - `rustfmt --edition 2021 <file>` only on files the task touched. **Never run it on `src-tauri/src/lib.rs`**: it walks every module. Edit lib.rs by hand in rustfmt style.
  - `./node_modules/.bin/biome check --write <files>` only on touched web files.
- **Secrets:**
  - The secret access key is decrypted only in Rust and never returned to the webview, never logged, and never put in an error message.
  - Saving with an empty or absent `secretAccessKey` keeps the stored one (the same patch rules as identities: absent or `""` keeps it, `null` clears it, text sets it).
- **Table and record name:** `storage_accounts`, everywhere: server table, client table, `record_type`/AAD, and the web table union.
- **Providers:** `"aws" | "r2" | "b2" | "wasabi" | "spaces" | "custom"`. Endpoints:
  - aws: `https://s3.{region}.amazonaws.com`
  - r2: `https://{r2AccountId}.r2.cloudflarestorage.com`, region `auto`
  - b2: `https://s3.{region}.backblazeb2.com`
  - wasabi: `https://s3.{region}.wasabisys.com`
  - spaces: `https://{region}.digitaloceanspaces.com`
  - custom: the given endpoint
- The object user-metadata key for the source time is `mtime`, in decimal seconds.
- The single-copy limit is `COPY_LIMIT = 5 * 1024 * 1024 * 1024` bytes. A rename refuses before moving anything if any object is larger.
- **No old-server fallback.** The identities fallback is removed: `TABLES_OLD_SERVERS_REJECT`, `without_tables_old_servers_reject`, `server_lacks_identities`, `lacks_identities`, and their tests.
- Out of scope (spec non-goals): edit-in-own-app and the in-app editor for bucket panes, upload resume, AWS profiles, bucket administration, WebDAV and FTP.
- **Bucket is required.** OpenDAL's S3 operator is bucket-scoped and has no ListBuckets.
  - The spec's "empty bucket = list buckets" is replaced by a required bucket field.
  - Several buckets mean several accounts.
  - Ruling: listing buckets would need our own signed S3 request next to OpenDAL. If wrong, it's a follow-up that adds `storage_list_buckets`.
- Clean-room: never copy or run termoso/AGPL code.

   - Test: `remote_target_picks_a_free_name_without_replace` (Task 5).
