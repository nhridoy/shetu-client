# WebDAV Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add WebDAV servers (Nextcloud/ownCloud, NAS, others) as a storage provider. They get pinned self-signed certificates and streaming uploads, and they reuse the S3 accounts, panes, transfers and compare.

**Architecture:** `webdav` becomes a provider in the existing `storage_accounts` blob. Rust builds an OpenDAL WebDAV `Operator`, with a per-account reqwest client when a certificate is pinned. The remote transfer side becomes a small struct that carries the operator plus, for WebDAV, what a streaming PUT needs. The web side extends the Storage form and adds a certificate-trust dialog.

**Tech Stack:** Rust (opendal 0.59 `services-webdav`, reqwest 0.13, rustls 0.23 with ring, rustls-platform-verifier, tokio-rustls), React 19, zustand, vitest, biome.

**Spec:** `docs/superpowers/specs/2026-11-20-webdav-design.md`

## Global Constraints

- **No attribution:** never add Claude or AI attribution anywhere.
- **Formatting:**
  - Run `rustfmt --edition 2021 <file>` only on files the task touched. Never run it on `src-tauri/src/lib.rs`, or on `db.rs` or `sync_db.rs` unless the diff stays confined to your lines.
  - Run `./node_modules/.bin/biome check --write <files>` on touched web files, from the repo root.
- **No aws-lc:** TLS uses the ring provider the app already compiles; no `aws-lc-sys` may enter `Cargo.lock`. Check with `cargo tree -i aws-lc-sys` and expect "did not match".
- **The password is a secret:** decrypted only in Rust, never in a view, log or error. The patch rules are the same as `secretAccessKey`: absent or `""` keeps it, `null` clears it, text sets it.
- **Field names in the encrypted blob:** `webdavKind` (`"nextcloud"` | `"other"`), `server`, `url`, `username`, `password`, `trustedCertSha256` (lowercase hex, 64 characters).
- **Nextcloud URL:** `https://{server}/remote.php/webdav/`, where `server` is the host plus an optional port or path prefix, with no scheme and no trailing slash.
- **The certificate error string** returned by `storage_connect` and `storage_test` is `cert:` followed by JSON `{"kind":"untrusted"|"changed","host":"<host:port>","sha256":"<hex>","previous":"<hex>"|null}`. The web side parses the `cert:` prefix.
- **The streaming upload sends** `X-OC-Mtime: <seconds>` when the source mtime is above 0, and `If-None-Match: *` when `if_not_exists` is set. 200, 201 and 204 mean success.
- **The `mtime` user metadata is never written for WebDAV operators.**
- **Background transfers never prompt about certificates.** An untrusted certificate fails the job with the message "The server's certificate isn't trusted — open the account to review it".

## Review Focus

1. **A pinned certificate that the server later replaces.** The connection must be refused with a `changed` error, never accepted silently.
   - Test: `pinned_verifier_refuses_a_different_certificate` (Task 2).
2. **An upload larger than memory would hold** (hundreds of MiB). It must stream with constant memory and arrive byte for byte.
   - Test: `streaming_put_sends_the_whole_body_in_chunks` (Task 4, 20 MiB through a test server).
3. **A Nextcloud server entered with a scheme, a trailing slash or a port** (`https://cloud.example.com:8443/`). The URL must still be built correctly.
   - Test: `nextcloud_url_normalises_server` (Task 1).
4. **Renaming a WebDAV folder.** It must use the server's MOVE, with no count prompt and no 5 GiB check, and still refuse an existing name.
   - Tests: `rename_uses_native_move_when_supported` (Task 3) and `asks before renaming only for buckets` (Task 6).
5. **Forgetting a pinned certificate.** It must remove the pin so the next connect asks again.
   - Test: `null_trusted_cert_clears_the_pin` (Task 1).

  - `pub struct DavTarget { pub base: String, pub username: String, pub password: String, pub client: reqwest013::Client }`, defined in `storage/webdav.rs`. Task 4 adds the PUT.
  - `pub fn remote_for(d: &StorageAccountData) -> Result<Remote, String>`. It keeps `operator_for` for S3 internally. For WebDAV it builds:
    - the OpenDAL WebDAV builder, with `endpoint` as scheme and authority, `root` as the URL path, plus `username` and `password`;
    - when pinned, `op.with_context(OperationContext::new().with_http_transport(HttpTransporter::new(ReqwestTransport::new(client))))`;
    - the same retry and timeout layers as S3;
    - `dav = Some(DavTarget { base: webdav_url, .., client })`.
  - `io::Side::Remote(Remote)`, replacing `Side::Remote(Operator)`. Every arm uses `r.op`.
  - `StorageSessions` stores `(StorageRef, Remote)`. `operator_for_ref` becomes `remote_for_ref(..) -> Result<Remote, String>`, and `op()` returns `Remote`.
  - `pub async fn cert_error(d: &StorageAccountData, e: &str) -> Option<String>`: for an `https` WebDAV account whose connect failed, it probes once. It returns the `cert:` error string when the probe's fingerprint isn't publicly trusted: `kind` is `"changed"` when a pin exists and differs, otherwise `"untrusted"`. Otherwise it returns `None`.
  - `storage_connect` and `storage_test` map their access-check failures through `cert_error` first.
  - `ops::rename_tree`: when `op.info().capability().rename`, a file or a folder is one `op.rename(from_key, to_key)` call, after the existing "already exists" check. Otherwise the existing copy-then-delete runs.

    not `Connection`, so a background job fails plainly instead of retrying.
    `pub fn is_cert_error(e: &(dyn std::error::Error + 'static)) -> bool` in `storage/tls.rs`
    walks the source chain looking for `rustls::Error::InvalidCertificate`.
  - For WebDAV, `io::open_part` never adds `user_metadata`. The `dav.is_some()` check comes first; Task 4 takes over that branch.

### Task 4: Streaming WebDAV upload

**Files:**
- Create: `src-tauri/src/storage/webdav.rs` (`DavTarget` plus the PUT).
- Modify: `src-tauri/src/transfers/io.rs` (the writer variant).

**Interfaces:**
- Consumes: `Remote` and `DavTarget` (Task 3), and `WriteOpts` (existing).
- Produces:
  - `pub fn status_error(status: u16) -> Option<JobError>`:
    - `None` for 200, 201 and 204;
    - `Operation` for 401, 403, 404, 405 and 409, with messages naming the cause (sign-in refused, folder missing, …);
    - `Operation(DEST_CHANGED)` for 412;
    - `Connection` for 5xx and everything else.
  - `pub struct DavUpload`. `DavTarget::start_put(&self, key: &str, opts: WriteOpts) -> DavUpload` spawns `client.put(url).basic_auth(..).header(..).body(Body::wrap_stream(rx))`. `DavUpload::send(&mut self, chunk: Vec<u8>) -> Result<(), JobError>` feeds the channel, and `DavUpload::finish(self) -> Result<(), JobError>` closes it and maps the response with `status_error`.
  - The URL is `base` joined with the key, with each segment percent-encoded (spaces, `#`, `+` and unicode stay correct).
  - `io::Writer::Dav(DavUpload)`, chosen in `open_part` when `r.dav` is `Some`. Dropping it aborts the request, so nothing needs to be cleaned up.

  - `status_error_maps_webdav_replies`: 201 and 204 give `None`; 401 gives `Operation`; 412 gives `Operation(DEST_CHANGED)`; 507 gives `Connection`.
  - `streaming_put_sends_the_whole_body_in_chunks`:
    - A tiny HTTP server (a `TcpListener` task that reads the request headers, then reads the body to the end, honouring `Transfer-Encoding: chunked` or `Content-Length`) receives a 20 MiB upload sent as 320 sends of 64 KiB through `io::copy` from a local file to `Side::Remote(Remote { op, dav: Some(..) })`.

  - `if_not_exists_sends_if_none_match`: the header `If-None-Match: *` is present when `if_not_exists` is set.
