# App Lock Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Lock Shetu while it keeps running (idle time, Lock now, system sleep/screen lock), wiping vault keys and covering the window until the master password is entered.

**Architecture:** One `lockApp()` action in the auth store (wipes keys via `lock_session`, sets `appLocked`), a full-window `LockScreen` that replaces `UnlockDialog` while `appLocked`, a frontend trigger layer (idle timer, `app.lock` shortcut, sidebar button, `system-lock` Tauri event), and a Rust `system_lock` module that turns native OS sleep/screen-lock signals into that event.

**Tech Stack:** React 19, zustand, vitest; Rust with `zbus` 5 (Linux), `windows` 0.62 (Windows), `objc2`/`objc2-foundation`/`objc2-app-kit` 0.3 + `block2` (macOS) — all already in Cargo.lock via Tauri; add them as target-specific direct deps.

**Spec:** `docs/superpowers/specs/2026-11-16-app-lock-design.md`

## Global Constraints

- On lock: keys wiped (`lock_session`); terminals, transfers and forwards keep running; sync stops until unlock.
- Unlock: master password only via the existing `unlock(password)`; the keychain password must never skip an app lock.
- Settings (per device, `settings.json`): `lockAfterIdleMinutes` ∈ {0, 1, 5, 15, 30, 60}, default `0` (Off); `lockOnSystemLock` boolean, default `true`.
- Shortcut `app.lock`: `ctrl+shift+l` (Linux/Windows), `shift+meta+l` (macOS), label "Lock Shetu", context `app`, fires while typing.
- Lock screen: full-window, opaque, nothing behind it visible or focusable; password field focused; "Sign out" link.
- Only user input (keydown, pointerdown, pointermove, wheel) resets idle; terminal output doesn't.
- `biome check --write` only on changed files. No AI attribution in commits.

## Review Focus

- A key pressed while locked reaches neither the terminal nor any shortcut (palette, new tab…) (Task 1 test `shortcuts_and_terminal_input_blocked_while_locked`).
- Locking while a modal is open (host form, palette, Run on hosts) → the lock screen still sits on top and those modals can't be used (Task 1 test `lock_screen_covers_open_dialogs`).
- Two triggers at once (idle + sleep event) → one lock, no errors (Task 2 test `repeated_lock_is_a_no_op`).
- The app is signed out or not yet unlocked when a trigger fires → nothing happens (Task 2 test `triggers_ignored_when_not_unlocked`).
- Wrong password several times → stays locked with the error each time; Sign out still works (Task 1 test).

### Task 3: Native sleep / screen-lock events (Rust)

**Files:**
- Create: `src-tauri/src/system_lock.rs`
- Modify: `src-tauri/src/lib.rs` (`mod system_lock;` and `system_lock::start(app.handle().clone())` in `.setup`), `src-tauri/Cargo.toml` (target deps: Linux `zbus = { version = "5", default-features = false, features = ["tokio"] }`; Windows `windows = { version = "0.62", features = ["Win32_Foundation", "Win32_UI_WindowsAndMessaging", "Win32_System_RemoteDesktop", "Win32_System_LibraryLoader", "Win32_System_Power"] }`; macOS `objc2`, `objc2-foundation`, `objc2-app-kit` 0.3 with the notification features, `block2` 0.6)

**Interfaces:**
- `pub fn start(app: tauri::AppHandle)`: starts the platform listener on its own thread/task; never panics or blocks setup; a listener that can't start just logs (e.g. no logind).
- Emits Tauri event `"system-lock"` (payload: `"sleep"` or `"screen"`).
- Linux: system-bus `org.freedesktop.login1.Manager` signal `PrepareForSleep(bool)` → emit `"sleep"` when `true`; `org.freedesktop.login1.Session` at `/org/freedesktop/login1/session/auto` signal `Lock` → emit `"screen"`. Pure helper `fn linux_signal_reason(member: &str, start: Option<bool>) -> Option<&'static str>`.
- Windows: message-only window (`HWND_MESSAGE`) on a dedicated thread; `WTSRegisterSessionNotification(hwnd, NOTIFY_FOR_THIS_SESSION)`; `WM_WTSSESSION_CHANGE` with `WTS_SESSION_LOCK` → `"screen"`; `WM_POWERBROADCAST` with `PBT_APMSUSPEND` → `"sleep"`.
- macOS: `NSWorkspace.sharedWorkspace.notificationCenter` observer for `NSWorkspaceWillSleepNotification` → `"sleep"`; `NSDistributedNotificationCenter.defaultCenter` observer for `"com.apple.screenIsLocked"` → `"screen"`. Observers registered on the main thread (in `setup`) and kept alive for the app's lifetime.
